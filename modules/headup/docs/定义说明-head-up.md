# 定义说明 · 抬头与匿名人数口径 `head-up-attendance-qwen-vl-v2`

日期：2026-09-20。本文件是抬头专用文档 §5 要求的"definitionId 配套说明"：
说明**采用什么抬头判定、什么对象进入分母、哪些对象排除、遮挡如何判无效、每窗如何选帧、
窗口是否代表估计、实际支持帧率/时长与处理耗时**。

> ⚠️ 实现阈值属于算法配置及版本，不由主项目凭空确定；任何修改都要**更新版本号**，
> 并同步 `src/headup/definitions.py`、本文件与交付 fixture。

## 1. 口径与版本登记

| definitionId | 用途 | 口径文本（`payload.denominatorDefinition`） |
| --- | --- | --- |
| `head-up-attendance-qwen-vl-v2` | 真实处理（本部署默认） | 代表帧内匿名可见学生人数；排除教师、助教、访客、媒介人物、反射和重复影像；抬头率分母仍为可判断头部状态的学生人数；跨窗人数只作稀疏截图估计 |
| `head-up-qwen-vl-v1` | 历史真实处理 | 代表帧内可判断抬头状态的可观测人数（head_up + head_down）；不用于出席率 |
| `head-up-demo-v1` | 合成 fixture（主项目文档包登记值） | 合成样例：代表帧内可判断抬头状态的可观测人数，非应到或实到人数 |

**观测口径版本（v0.2 起）**：默认提示词为 `headup-strict-v0.2`（严格观察口径）——
只依据直接可见的视觉证据，只见后脑/背对镜头必须判 UNKNOWN，禁止推测。
模型返回自洽五计数（`up + down + unknown = visible`、`up + down = evaluable`），
`head_up_rate` 与 `coverage` 由程序计算。旧口径 `headup-prompt-1` 保留，可显式启用。
详见 [`rounds/Round1-严格口径.md`](rounds/Round1-严格口径.md)。

口径 ID 与口径文本在 `src/headup/definitions.py` 中**成对维护**：只改 ID 不改文本会在启动时
直接报错（`Config.load()` 的一致性检查），避免主项目登记到错配的口径说明。

## 2. 判定规则（三分类）

先匿名统计代表帧中的**可见学生**，再将每名学生的头部状态判定为且仅为一类：

| 类别 | 判定依据 | 是否进分母 | 是否进分子 |
| --- | --- | --- | --- |
| `head_up` | 面部朝向讲台/正前方/黑板/屏幕，能看出抬头注视姿态 | ✅ | ✅ |
| `head_down` | 明显低头看桌面、纸笔、手机，或趴伏 | ✅ | ❌ |
| `unknown` | 背对镜头；侧脸且姿态不可辨别；被前排/设备遮挡；画面过糊或过小 | ❌ | ❌ |

于是：

```
headUpCount        = head_up
validObservedCount = head_up + head_down          （可判断者）
headUpRatio        = headUpCount / validObservedCount   （RATIO_ONLY 模式下由模块给出）
```

**明确不做的事**：不识别身份、不建学生档案、不推断"应到/实到"、不把 `validObservedCount`
解释为班级人数。分母是"可判断者"，不是"全班人数"——这一点在报告文案里必须保持一致。

## 3. 分母定义与排除对象

抬头率分母 = **代表帧内可判断抬头状态的学生人数**。匿名人数 = **代表帧内可确认存在的学生人数**。两者都排除：

1. 教师、助教、访客、屏幕或海报人物、镜面反射和重复影像；
2. 空座、书包、衣物及完全遮挡位置推测出的人；
3. 背对镜头/侧脸且姿态不可辨别的学生（不进抬头率分母，但仍可进匿名可见人数）；
2. 被前排人体、课桌、显示器、讲台设备遮挡的人；
3. 因运动模糊、失焦、分辨率过低而无法判断的人；
4. 画面边缘被裁切到只剩局部、无法确认是否为人的人。

排除的人不会被计入分子，也**不会被假定为低头**——这是与"低头即不专注"这类推断的分界线。

## 4. 遮挡与画面质量如何判无效

| 情况 | 结果 | quality | 计数 |
| --- | --- | --- | --- |
| 画面里没有人（空教室、镜头对墙、只拍讲台） | 整帧无可观测对象 | `NO_SUBJECTS` | 固定 `0/0`，`headUpRatio=null` |
| 有人在但一个都判断不了（全遮挡/全背对） | 无可用观测 | `LOW_QUALITY`，原因 `NO_LEGIBLE_SUBJECTS` | 两数 `null` |
| 可判断者存在，但可判断比例 < `MIN_LEGIBLE_RATIO` | 画面质量不足 | `LOW_QUALITY`，原因 `LOW_LEGIBLE_RATIO` | 两数 `null` |
| 取帧失败（该时间点无可用画面） | 抽帧失败 | `LOW_QUALITY`，原因 `FRAME_EXTRACTION_FAILED`，`sampleAtMs=null` | 两数 `null` |
| 模型调用失败（超时/限流/返回非法） | 单窗失败 | `LOW_QUALITY`，原因 `ANALYSIS_FAILED` | 两数 `null` |
| 全部窗口都不可用 | 整体失败 | 任务 `FAILED` + `PROCESSING_FAILED` | 无 payload |

`LOW_QUALITY` **绝不**用 0 或"没有人"来冒充；`NO_SUBJECTS` 与"真实 0% 抬头"是两回事：

- 真实 0：`VALID` + `0/N`（N>0）；
- 没人：`NO_SUBJECTS` + `0/0` + `headUpRatio=null`。

## 5. 每窗如何选帧

- 请求给出 `windowMs`，把 `analysisRange` 切成左闭右开窗口，末窗可短；
- **每个窗口取一帧**作为该窗口的估计值（`sampleMode = REPRESENTATIVE_FRAME`）；
- 帧位置由 `HEADUP_SAMPLE_POSITION` 决定：`start`（窗口第 1 毫秒）/ `middle`（默认，中点）/ `end`（窗口最后 1 毫秒）；
- `sampleAtMs` 落在 `[startMs, endMs)` 内，使用**原媒体毫秒轴**；
- 窗口是否代表估计：**是估计值**。单帧抽样不能宣称是连续行为测量，主项目展示时也必须如此说明。

可选增强（默认关闭）：`FRAME_TILE_GRID=2x2|3x2` 把一帧切块分别计数后求和，用于降低密集小目标漏计；
分块会改变有效口径，开启时应同时在部署记录里注明。

## 6. 阈值与可配置项

| 配置 | 环境变量 | 默认 | 作用 |
| --- | --- | --- | --- |
| 可判断比例下限 | `MIN_LEGIBLE_RATIO` | `0.60` | 低于此值整窗判 `LOW_QUALITY` |
| 抽帧宽度上限 | `FRAME_MAX_WIDTH` | `1600` | 抽帧后缩放宽度，控制模型输入体积 |
| 模型输入长边 | `VISION_MAX_LONG_SIDE` | `2048` | 送入模型前的最大边长 |
| 模型输入字节 | `VISION_MAX_IMAGE_BYTES` | 9 MB | 超过则继续降低 JPEG 质量 |
| 分块 | `FRAME_TILE_GRID` / `FRAME_TILE_OVERLAP` | `1x1` / `0.08` | 见 §5 |
| 判定模型 | `VISION_MODEL` / `VISION_FALLBACK_MODEL` | `qwen3-vl-plus` / `qwen3-vl-flash` | 主模型失败且错误可重试时切备用 |
| 采样位置 | `HEADUP_SAMPLE_POSITION` | `middle` | 见 §5 |

这些阈值**都是本模块的算法配置**，不是教学评价标准；主项目不据此设"低抬头"评分线。

## 7. 支持的媒体与耗时

| 项 | 现状 |
| --- | --- |
| 媒体格式 | 由 ffmpeg/ffprobe 决定（容器/编码未逐一实测；MP4/H.264 已实测） |
| 必须含视频流 | 是；无视频流 → `UNSUPPORTED_MEDIA` |
| 时长上限 | `MEDIA_MAX_DURATION_MS`（默认 2 小时，**未实测**） |
| 窗口数上限 | `MAX_WINDOWS`（默认 20000） |
| 处理耗时 | 单窗通常为 1 次抽帧 + 1 次模型调用；真实时延受供应商排队、复核与重试影响 |
| 并发 | 单任务主识别默认最多 4 个独立请求并发；复核判定仍按时间顺序应用 |
| 多镜头/变速/拼接 | 不支持（时间映射不可恢复时应 `UNSUPPORTED_MEDIA`） |

## 8. 已知局限（必须随结果一起展示）

1. **单帧估计**：抬头率是代表帧的估计，不是连续行为测量；真实课堂中 10 秒内姿态变化可能很大。
2. **视角偏差**：后排、侧向机位、俯拍摄像头的可判断比例低，会更多落入 `LOW_QUALITY`，使有效覆盖下降。
3. **遮挡**：前排人体/设备遮挡后排时，被遮者被排除在分母外，可能让抬头上限被高估。
4. **模型会"猜"看不清朝向的人**（2026-09-14 实测）：在"多人仅见后脑"的俯拍画面里，
   现行提示词把 4 个人算成了抬头；换成严格提示词（看不见眼睛一律 `unknown`）后降为 0。
   是否升级提示词属**口径变更**，见 §9。
5. **输出不可逐位复现**（实测）：同一帧重复调用有 ±1 人量级抖动；靠近阈值的窗口可能在
   `VALID` 与 `LOW_QUALITY` 之间翻转。同一媒体整段重跑，平均抬头率差异约 3 个百分点。
   ⇒ 展示时应写"本次运行估计值"，不要写成精确测量。
6. **换模型会显著改变数值**（实测）：`qwen3-vl-plus` 0.715 vs `qwen3-vl-flash` 0.588（同一媒体）。
7. **低头 ≠ 不在学**：低头可能是记笔记；本模块只报姿态，不做学习状态推断。
8. **不可判断者不假定为低头**：因此分母会小于画面人数，报告需说明。
9. **无身份信息**：同一人跨帧不关联，`windows` 之间不可求和为人次或人数。主项目只取最高三个有效人数观测的中位数。
10. **人数仍是截图估计**：视野外、遮挡、教师误分类和模型计数抖动都会造成偏差，不作为正式考勤。

## 9. 实测结论与待决策（2026-09-14）

完整数据见 [`测试记录-真实模型.md`](fixtures/head-up-module-v0.1/测试记录-真实模型.md)，
逐条对应到口径：

| 观察 | 对口径的影响 | 状态 |
| --- | --- | --- |
| 模型把"只见后脑"的人算成抬头 | 分子被高估 ⇒ 抬头率偏高 | **待评审**：是否启用严格提示词（`headup-prompt-2`） |
| 严格提示词下"全班 100% 抬头"仍会出现 | 分子可能整体偏乐观 | 需要人工标注集才能定量 |
| 同帧抖动 ±1 人、整段均值抖 ±3 个百分点 | 报告不得写成精确值 | 已在 README/交接表标注 |
| 阈值附近窗口质量翻转（legible 0.600 ↔ 0.533） | `MIN_LEGIBLE_RATIO=0.60` 卡在临界 | 待真实课堂分布数据后再定 |
| `2x2` 分块在本轮素材上更差（legible 0.47 vs 0.78，耗时 ×4） | 分块不是默认更优解 | 保持默认 `1x1` |

**在这些问题定案前**：报告必须标注"AI 估计，未经人工核对"，且页面上的抬头率要带
"代表帧估计 / 本次运行"字样，不能表述为学生的真实专注度。

## 9. 在本机核对单帧判定（改提示词前必做）

```powershell
# 1) 抽一帧出来看（用真实课堂视频的中间时刻）
.\scripts\Run.ps1 -Target frame -CliArgs @('--file','课堂.mp4','--at','600000','--out','.work\frame-600s.jpg')

# 2) 配置 DASHSCOPE_API_KEY 后，直接跑一遍完整流水线并保留逐窗判读记录
$env:DASHSCOPE_API_KEY='sk-…'
.\scripts\Run.ps1 -Target cli -CliArgs @('run','--file','课堂.mp4','--window-ms','10000',
                                         '--reports','.work\reports.json','--out','.work\envelope.json')

# 3) 用 stats-v1 重算统计，和页面数值对一下
.\scripts\Run.ps1 -Target cli -CliArgs @('stats','--envelope','.work\envelope.json')
```

`--reports` 写出的逐窗记录包含：该窗代表的帧路径、模型原始计数、`unknown` 数、可判断比例、
模型自报置信度、命中的阈值与最终 quality——**人工复核只需看这份文件**。

> 未经真实课堂数据验证前，不要对外宣称任何精度数字。当前仓库里唯一的"真实媒体结果"来自
> 合成示意图（4×5 人形轮廓），只证明链路与降级行为，不证明识别准确率。
