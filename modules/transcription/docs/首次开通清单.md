## 0. 先看这张表，决定你要开通哪一家

| 提供方 | 值 | 契约路径可用？ | 要准备什么 |

## 1. TokenHub（推荐，当前唯一可用）

### 步骤 1.1 · 拿到 API Key

1. 登录腾讯云控制台，进入 TokenHub 的 API Key 管理页：
   <https://console.cloud.tencent.com/tokenhub/apikey>
2. 新建 API Key 并**立刻复制**（多数控制台只在创建时显示一次）。
3. 进入推理服务页，**开通后付费或领取免费额度**：
   <https://console.cloud.tencent.com/tokenhub/inference>

> ⚠️ **不开计费会直接失败**。实测错误码：`401007`（无免费额度且未开后付费），HTTP 402。
> 这个坑很容易踩：Key 本身是有效的，报错却像是鉴权问题。

### 步骤 1.2 · 填进 `.env`

```powershell
Copy-Item .env.example .env      # .env 已在 .gitignore 中，不会入库
notepad .env
```

```ini
ASR_PROVIDER=wand
WAND_API_KEY=sk-你的Key
WAND_BASE_URL=https://tokenhub.tencentmaas.com
WAND_MODEL=wand-asr-v1
```

**`.env` 不会被 Spring 自动读取**，需要用 `scripts/Use-Env.ps1` 载入：

```powershell
. .\scripts\Use-Env.ps1
.\scripts\Start.ps1
```

### 步骤 1.3 · 确认接入成功

启动日志里应有 `AsrStartupCheck` 打的一行：

```
ASR 提供方: WAND / 模型 wand-asr-v1（内联音频: 支持，URL 暂存: inline-only（不支持暂存为公网 URL），轮询上限 PT2H）
```

然后照 README §2.3 提交一个任务。要真正验到"识别成功"，还需要一个
**公网可达、sha256 与请求一致**的媒体地址——本地联调可以用
`MEDIA_ALLOW_LOOPBACK_HTTP=true` 配合 `lvh.me` 这类指向 127.0.0.1 的公网域名。

### TokenHub 错误码对照（**本模块实测**，见 `TokenHub接口探测记录.md`）

| 错误码 | 含义 | 你要做什么 |
| --- | --- | --- |
| `401002` | API Key 不存在或签名校验失败 | 回步骤 1.1，检查 Key 是否复制完整 / 是否已吊销 |
| `401006` | service ID 不存在或与 model 不匹配 | 检查 `WAND_MODEL` 是否写成了不存在的模型名 |
| `401007` | **无免费额度且未开后付费**（HTTP 402） | 回步骤 1.1 开通计费 |
| `400001` | 缺必填字段 | 模块 bug，请附请求体反馈 |
| `400002` | 参数取值非法 | 检查音频格式与时长 |
| `400004` | task not found | 任务 ID 不存在，或结果已过 **24 小时**保留期 |
| `502001` | 上游引擎失败 | 可能是音频临时不可达，可重试 |

## 2. 阿里云百炼（代码就绪，缺暂存）

> 只有当你已经决定要走阿里云那条路（12 小时 / 2GB 长音频、说话人分离、热词）时才做这一节。
> **做之前请先确认第 2.3 步的存储问题有答案**，否则开完也跑不通。

### 步骤 2.1 · 开通百炼并拿 API Key

1. 登录阿里云百炼控制台：<https://bailian.console.aliyun.com/>
2. 需要**实名认证**；非北京地域注意模型可用范围，本模块默认按**华北2（北京）**写。
3. 在 **API-KEY 管理**里新建 Key 并复制。
4. 在**模型广场**确认 `qwen-audio-3.0-asr-flash-filetrans` 可用（这是本模块选定的模型）。

计费口径是**音频时长（每秒）**，北京地域 0.00022 元/秒 ≈ **0.79 元/小时**；
45 分钟一节课约 **0.59 元**。

### 步骤 2.2 · 业务空间 ID（WorkspaceId）——**可选**

专属域名形如 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1`，
`{WorkspaceId}` 在控制台的业务空间设置里（官方指引：
[获取 Workspace ID](https://help.aliyun.com/zh/model-studio/obtain-the-app-id-and-workspace-id)）。

> ✅ **2026-09-15 实测：不填也能跑通。** 公共域名 `dashscope.aliyuncs.com` 直接接受
> `sk-ws-…` 形态的 Key，提交/轮询/取结果全部正常。
> 官方称专属域名"性能与稳定性更好"，所以**生产建议配**，但它不是可用性的前提。

### 步骤 2.3 · 解决音频公网可达问题（**这一步没有现成答案，也是唯一还缺的**）

阿里云长音频档**不接受 Base64、不接受二进制流、不接受本地文件**，
只认"公网可访问的 URL"（官方 FAQ 原文）。所以必须先把音轨暂存出去。

三条可选路线：

| 选项 | 前提 | 代价 |
| --- | --- | --- |
| **新建 OSS 桶，本模块上传并生成预签名 URL**（推荐） | 一个 bucket + 写入凭证 | 每课上传约 86 MB（45 分钟 16k 单声道 WAV）+ 一份临时对象 |
| 复用主项目已有的媒体桶 | 主项目愿意划一个可写前缀 | 需与主项目约定前缀命名与清理策略 |
| 直接把 `sourceUrl` 转给引擎 | 该地址本身公网匿名可读 | **不建议**：sha256 核验语义失效，见下 |

> ⚠️ 第三条为什么标"不建议"：契约 §3 要求模块自己下载并核验 SHA-256。
> 把 `sourceUrl` 转手给第三方下载，模块就**无法证明引擎读到的是它校验过的那份字节**。
> 这种失真**不报错、只失效**——从外部完全看不出来。所以当前代码宁可明确失败，
> 也不默默回退（`InlineAudioStaging` + 启动 ERROR 提示）。
>
> 📌 **想先验证阿里云识别本身**（不配暂存）可以直接跑真机测试，它会用官方公开样例音频：
>
> ```powershell
> $env:MANUAL_ASR_TEST_KEY = "sk-..."
> mvn -B -s .mvn/settings-sandbox.xml test "-Dtest=ManualAliyunLiveTest"
> ```

### 步骤 2.4 · 填进 `.env`

```ini
ASR_PROVIDER=aliyun-filetrans
DASHSCOPE_API_KEY=sk-你的Key
# 可选；不填则走公共域名 dashscope.aliyuncs.com（实测可用）
DASHSCOPE_WORKSPACE_ID=你的业务空间ID
ALIYUN_ASR_MODEL=qwen-audio-3.0-asr-flash-filetrans
# 说话人分离（仅单声道，本模块抽的就是单声道；建议音频 ≤2 小时）
ALIYUN_ASR_DIARIZATION=true
# 语种提示：实测 filetrans 接受该参数（官方参数表只列了 paraformer-v2，是文档滞后）。
# 中英混说的课建议打开——但"被接受"不等于"更准"，要断言得用真实课堂音频做对照
ALIYUN_ASR_LANGUAGE_HINTS=zh,en
```

没有配好第 2.3 步之前，启动日志会有一行 ERROR：

```
ASR 配置不可用：提供方 ALIYUN_FILE_TRANS 只接受公网 URL（不接受内联音频），
但当前 AudioStaging 是「inline-only（不支持暂存为公网 URL）」，无法产出 URL。
在此状态下每个转写任务都会以 PROCESSING_FAILED 结束。
```

看到这行就是第 2.3 步还没落地，**不是**代码坏了。

## 3. 拿到凭证之后：只有这几件事需要真机确认

上面两家都只是"能调通"，**不等于验收**。真正必须用真机确认的是：

1. **与主项目商定时间容差**（交接表 §6.2）——契约要求 M4 用同一段真实媒体核对
   起点/中点/末尾各一处。**这是最需要主项目配合的一项，目前数值未确定。**
2. **阿里云的"文档值 vs 实测值"**（[`阿里云模型选型.md`](阿里云模型选型.md) §5 那张表右列目前全空），
   其中三项最容易出问题：
   - 轮询到底是 `GET /api/v1/tasks/{id}` 还是 `POST`（代码按前者实现，若 405 只改一处）；
   - `language_hints` 在 filetrans 上是否真的被接受（官方两处表述矛盾）；
   - `transcription_url` 指向的 JSON 字段名是否与官方样例一致。
3. **真实课堂音频的识别质量**（字准率、远场/噪声）。本模块只转发引擎结果，不做质量评估，
   但"能不能用"最终由这个决定。
4. **TokenHub 的内联体积上限**：2 小时 16k 单声道 WAV ≈ 230 MB，base64 后 ≈ 307 MB，
   而本模块**没有内联体积守卫**，TokenHub `data` 通道的实际上限文档未给（只实测过 4 MB）。
